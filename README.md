# РЕВИЗИЯ — инвентаризация с одного телефона

Мобильное веб-приложение на React + Vite: импорт XLSX/CSV, штрихкоды через камеру, ручной поиск по наименованию или артикулу, запись коробок/штук, сохранение сессии на телефоне и экспорт Excel.

## Быстрый старт

```bash
npm install
npm run dev
```

Для публикации на Vercel: Framework Preset **Vite**; Root Directory — корень проекта; Build command — `npm run build`; Output Directory — `dist`; Node.js 20/22. В браузере телефона нужен **HTTPS** для камеры.

## Работа с товаром без читаемого штрихкода

1. Экран **Сканер → Не сканируется штрихкод?** открывает поиск по названию, артикулу и штрихкоду из каталога Excel.
2. Нажмите на найденную позицию — откроется форма количества; записывайте коробки и отдельные штуки как обычно.
3. Если код считан, но в Excel его нет, нажмите **Найти товар в каталоге**. После выбора позиции и сохранения подсчёта считанный код будет связан с этой позицией и распознаваться при следующем сканировании.
4. Если товара совсем нет в исходной таблице, выберите **Добавить товар, которого нет в Excel**, заполните название (необязательно код и артикул) — новая позиция попадёт в отчёт.
5. Если невозможно определить товар, сохраните его в отдельном листе «Неизвестные».

## Формат импорта

Первая строка — заголовки. Обязательное поле **Наименование**; поле **Штрихкод** необязательно: строки без кода доступны через поиск. Дополнительные поля: **Артикул**, **Остаток**, **Штук в коробке**. На экране загрузки сопоставьте колонки вручную. Штрихкоды в Excel желательно хранить как текст (ведущие нули и коды длиннее 15 цифр).

## Итоговый XLSX

Пять листов: **Итоги**, **Расхождения**, **История**, **Неизвестные**, **Привязки кодов**. Повторные подсчёты суммируются. Ранее введённые количества редактируются через «Историю». Не просканированные товары имеют статус «Не посчитан» и не объявляются недостачей автоматически.

## Хранение и офлайн

Данные сохраняются только в браузере одного телефона, без авторизации или облака. Service Worker после успешной первой загрузки по HTTPS кэширует собранные файлы приложения для работы без интернета; камера может зависеть от устройства и браузера. **Очистка данных сайта удалит все локальные подсчёты** — регулярно выгружайте Excel. Обновление сайта и смена браузера не синхронизируют ваши данные.

## Ограничения MVP

* Параллельная работа нескольких сотрудников не предусмотрена.
* При создании новой инвентаризации текущий каталог и подсчёты заменяются; сначала сделайте экспорт.
* Успешность камеры, установка PWA и офлайн-запуск должны быть проверены на реальном целевом телефоне.


## Версия 3.0 — улучшения

* Поиск по каталогу и на странице товаров понимает несколько слов в любом порядке, различия `ё/е`, артикулы и привязанные штрихкоды.
* При успешном сканировании выбирается преимущественно задняя камера телефона. После сохранения одного товара тот же штрихкод можно сканировать снова.
* **Отсутствующий товар**: в карточке товара нажмите «Подтвердить отсутствие товара — 0 шт.»; позиция отмечается как проверенная, в Excel показывается недостача, если учётный остаток был больше нуля.
* **Резервная копия**: Настройки → Сохранить .json; восстановление из .json со сверкой структуры и пересчётом фактических количеств.
* У непросканированных товаров колонка «Расхождение» теперь пустая, пока не подтвержден подсчёт.


## GitHub и автоматическая проверка

Исходный код хранится в отдельном репозитории. GitHub Actions проверяет расчёты и сборку после каждого изменения в `main`. После подключения репозитория к Vercel новые коммиты в `main` будут автоматически публиковаться.

Для импортируемого файла Excel используйте `пример_импорта.xlsx`. Не загружайте рабочие остатки, если репозиторий публичный: в истории коммитов они могут остаться даже после удаления.
